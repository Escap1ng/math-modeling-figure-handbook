# 数学建模竞赛图表绘制实战手册

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

面向数学建模竞赛（APMCM / 国赛 / 美赛等）的**图表工作流与质量清单**：49 条编号规则 + 8 个图型模板 + 三轮提交前 QA + 可复制的 Matplotlib 代码骨架。规则只陈述可迁移的原则与通用失败模式，不绑定任何特定论文或题型——换任何赛题都可直接套用。

> 核心信念：**图是求解结果的导出件，不是结论的插画；表是图的抄写件，抄完必须回对。**

## 为什么需要这本手册

评审对图的信任 = **数据一致性 × 可读性 × 可检索性 × 论证完整性**。四者相乘，任何一项为零则整体归零。对大量优秀论文配图的系统审查显示，失分几乎都来自四类根因：

1. **证据脱节**——图与正文/表/摘要数字矛盾，证据图来自别的模型或别的范围，示意图冒充结果图；
2. **口径分裂**——同一物理量多套尺度/起点/单位/货币，总量与分量对不上，结果表是图的错误抄写件；
3. **工艺不合格**——有效字号过小、色标缺失或不可读、图例压数据、轴与刻度失效、软件痕迹残留；
4. **链条断裂**——无图题、编号混乱、正文不按号引用、题图跨页、目录/页脚/附录承诺不兑现。

本手册把四类根因拆成可逐条打勾的规则，并给出"画前—画中—画后—提交前"四个时间点的执行顺序。

## 快速开始

1. **画前**：读 [handbook.md](handbook.md) §1，把每问的结论句映射到图型，填"图任务清单"；复制 §5.1 视觉契约代码到绘图脚本头部。
2. **画中**：按 §2 的 DATA/AXIS/COLOR/LEG/ANN/SIZE 规则出图；用 §5 的预测图 / 敏感性带 / 热图 / 多面板骨架起步。
3. **画后**：按 §3 写题注、接编号与正文引用。
4. **提交前**：走 §4 三轮 QA 清单；时间不够走"10 分钟最小集"。
5. **机器自检**：

   ```bash
   pip install pymupdf
   python qa_figs.py submission.pdf
   ```

   输出：缺号/跳号、未被正文引用的图、引用了但无图题的编号、`??` 断引用、低分辨率位图预警、页脚总页数集合。

## 规则族一览

| 族 | 条数 | 核心问题 |
|---|---|---|
| DATA | 9 | 图是不是那份数据？口径唯一吗？伪影注释了吗？ |
| AXIS | 8 | 轴名/刻度/单位/基线/量程读得出来吗？ |
| COLOR | 6 | 颜色语义全篇一致吗？色盲可读吗？色标有效吗？ |
| LEG | 5 | 图例压数据吗？声明与可见曲线一一对应吗？ |
| ANN | 5 | 阈值/最优点/关键数字在图上吗？注释越界吗？ |
| SIZE | 5 | 版心内有效字号达标吗？矢量优先吗？软件痕迹清了吗？ |
| CAP | 5 | 题注格式唯一、编号连续、题图同页、题文相符吗？ |
| REF | 3 | 每图被按号引用吗？引用对号吗？承诺兑现吗？ |
| TAB | 3 | 是真三线表吗？表与图逐行回对了吗？口径声明了吗？ |
| TPL | 8 | 预测 / 敏感性 / 矩阵 / 图像证据 / 流程 / 多面板 / 对拍 / 设计图的标准画法 |

## 设计原则

- **通用化**：规则描述失败模式而非个案细节，避免把某几篇论文的特例当成规范；历史审查案例不随仓库分发。
- **数据管线优先**：求解脚本输出统一结果文件，所有绘图脚本只读该文件——从结构上保证"图是导出件"，而不是靠事后对账补救。
- **先设画布再导出**：有效字号 = 源字号 × 版心宽 ÷ 源画布宽；"大图缩印"是字号灾难的唯一根源。
- **诚实报告**：失败案例与负结果如实上图；零信息图不占版面。
